# ADR-0008: CI/CD & Testing

## Status

Accepted (2026-08-10)

## Context

Theobase is a monorepo with three packages (shared, worker, web) deployed to Cloudflare. Every PR must be type-safe, tested, and deployable before merge. The counting room dual-signoff workflow and offline sync are high-risk features that need E2E coverage.

## Decision

### Monorepo Structure

```
theobase/
├── packages/
│   ├── shared/          # Drizzle schema, Zod schemas, TypeScript types
│   ├── worker/          # Cloudflare Worker + Durable Objects
│   ├── web/             # React PWA (Vite + TanStack Router)
│   └── observability/   # Error/sync reporting client (@theobase/observability)
├── docs/
├── branding/
└── pnpm-workspace.yaml
```

One `tsconfig.json` base extended by each package. Shared types prevent drift between DO validation and PWA forms.

### Testing

| Layer             | Tool                                       | Scope                                                                              |
| ----------------- | ------------------------------------------ | ---------------------------------------------------------------------------------- |
| Schema validation | Vitest                                     | Drizzle schema → Zod validator correctness                                         |
| DO unit tests     | Vitest + `@cloudflare/vitest-pool-workers` | DO state transitions, role enforcement, batch lifecycle                            |
| React components  | Vitest + React Testing Library             | Button, Input, MemberList, BatchCard, etc.                                         |
| Integration       | Vitest                                     | DO + Worker middleware + auth flow                                                 |
| E2E               | Playwright                                 | Counting room dual-signoff, offline sync + reconnect, member lifecycle, CSV import |

Critical E2E flows:

1. Clerk registers church, adds first member, sends role invite to treasurer.
2. Two counters open a batch, enter records on separate devices offline, sync and confirm.
3. Counter dispute: mismatch → reconcile → both confirm → batch commits.
4. Treasurer views auto-populated tithe remittance, approves, submits.
5. Clerk views auto-populated annual report, approves, submits.

### CI Pipeline (GitHub Actions)

The pipeline is defined in `.github/workflows/ci.yml`. Jobs:

```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
jobs:
  typecheck:  # tsc --noEmit across all packages (web, worker, observability)
  lint:       # ESLint (web package)
  test:       # Vitest (web + worker; worker needs Cloudflare API token)
  e2e:        # Playwright (runs on every PR; currently continue-on-error)
  deploy-pages:   # wrangler pages deploy on merge to main
  deploy-worker:  # wrangler deploy on merge to main
```

Note: e2e currently runs on every PR (not gated to merge). Worker tests run under `@cloudflare/vitest-pool-workers` via `packages/worker/vitest.config.ts`.

### Environments

| Environment | URL                       | Purpose                                |
| ----------- | ------------------------- | -------------------------------------- |
| Preview     | `<pr>.theobase.pages.dev` | Per-PR deployment via Cloudflare Pages |
| Staging     | `staging.theobase.app`    | Fiji Mission beta testing              |
| Production  | `theobase.app`            | Live platform                          |

### Branch Strategy

- `main` is always deployable. All changes via PR.
- Feature branches named `feature/<description>`.
- PRs require: lint passes, typecheck passes, tests pass, at least one approving review.
- Squash merge to main. Linear history.

## Consequences

- `@cloudflare/vitest-pool-workers` is Cloudflare's official DO test harness and tightly coupled to Wrangler — it's the right choice but upgrading Wrangler may require upgrading vitest.
- Playwright E2E tests for offline sync require network interception (`page.route()`) to simulate connectivity loss. This is a well-supported pattern but adds setup complexity to the Playwright config.
- Preview deployments per PR give stakeholders a live URL to test before anything merges.
