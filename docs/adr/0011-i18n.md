# ADR-0011: Internationalisation — i18next

## Status

Accepted (2026-08-10)

## Context

Theobase serves 215+ countries in multiple languages. v1 ships English + Fijian Hindi. The architecture must support adding languages without code changes.

## Decision

**i18next + react-i18next with JSON namespaces.**

### Library

| Layer         | Choice                                                          |
| ------------- | --------------------------------------------------------------- |
| Core          | `i18next`                                                       |
| React binding | `react-i18next`                                                 |
| Extraction    | `i18next-parser` (CLI, scans code for `t()` calls)              |
| ICU support   | Built into i18next (plurals, select, number formatting)         |
| RTL           | Switched via `dir="rtl"` on `<html>`, driven by locale metadata |

### String Structure

```
packages/web/src/i18n/
├── en/
│   ├── common.json       # Buttons, labels, navigation
│   ├── membership.json   # Member forms, lifecycle states
│   ├── giving.json       # Counting room, batch, tithe/offering
│   └── reporting.json    # Reports, insights
├── hif/
│   ├── common.json       # Fijian Hindi
│   ├── membership.json
│   ├── giving.json
│   └── reporting.json
```

All four namespaces are registered at app initialisation in `packages/web/src/i18n/index.ts`. (Per-route lazy loading of namespaces is a future optimisation; today the counting room downloads membership strings too.)

### Locale Preferences

- **Church**: primary locale set at registration. Defaults to the Conference's locale. (Not yet wired — locale resolution is currently saved-preference → browser → English.)
- **Member**: override locale in profile. Sabbath School lesson distribution uses this. (Not yet shipped.)
- **Resolution order (today)**: saved preference (`localStorage`) → browser `navigator.language` → English fallback. The planned order is member override → church primary → browser → English.

### Numbers, Dates, Currency

Use browser-native `Intl` APIs — no library needed:

- `Intl.NumberFormat(locale, { style: 'currency', currency: churchCurrency })` for amounts.
- `Intl.DateTimeFormat(locale, { dateStyle: 'long' })` for dates.
- Tabular numbers everywhere (financial data must align).

### Translation Workflow (v2+)

Community contribution via Weblate or Crowdin. v1: hand-authored English + Fijian Hindi.

## Consequences

- JSON namespaces grow over time. The extraction CLI keeps keys in sync but stale keys must be manually pruned.
- RTL testing requires Playwright in Arabic/Persian locale — add to the E2E suite when the first RTL language ships.
- `i18next-parser` must run in CI (or pre-commit) to catch missing keys. A CI check: no key present in source that's missing from `en/` fallback.
